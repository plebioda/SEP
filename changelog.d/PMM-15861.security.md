`EXTENSIONS_INTERNAL_TOKEN` no longer passes the role check on every write. It is admitted only on the writes made with no user behind them, by the inventory sync, the Operations scan, ATW, the log stream, and PMM Server's bootstrap stepper and Operations switch, and gets 403 on every other write. A leaked token can no longer delete Operations hosts or services, start a bootstrap, decide inventory identity links, delete task definitions or manage periodic tasks. It can still do what those callers need: write the inventory rows the syncers own, dispatch, stop and sync any task execution, create or update any task definition, and drive the steps of an existing bootstrap run, so a leaked token must still be treated as able to run tasks on managed hosts.
